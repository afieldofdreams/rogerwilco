Start in two minutes

rogerwilco is a message format and a check. There is nothing to sign up for and the hosted service needs no key. Pick the way that fits you. Each one takes two or three steps and ends with a real reply you can read.

API

Plain HTTPS, JSON in, JSON out. No key.

  1. Check a line. This is the hand-over from the front page: pay invoice MD-2026-057, 5,400.00 pounds, to the account on file, on 2 October, under approval FD-0929. 
    curl -s https://rogerwilco.crox.io/validate \
  -H 'content-type: application/json' \
  -d '{"line": "RW1 HO scheduler-1 p=pay from=scheduler to=payer item=inv:MD-2026-057 ask=PAY rb=exec sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057 apref=FD-0929", "profile": "pay"}'

             "item": "inv:MD-2026-057",

  2. Check a readback. Send the hand-over you sent and the read-back that came back. Here the other agent read 5,100.00 instead of 5,400.00. 
    curl -s https://rogerwilco.crox.io/check-rb \
  -H 'content-type: application/json' \
  -d '{"ho": "RW1 HO scheduler-1 p=pay from=scheduler to=payer item=inv:MD-2026-057 ask=PAY rb=exec sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057 apref=FD-0929",
       "rb": "RW1 RB payer-1 re=scheduler-1 from=payer to=scheduler item=inv:MD-2026-057 ask=PAY p=pay h=a7a82de76607 sup=marlow amt=5100.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057 apref=FD-0929",
       "profile": "pay"}'
    {"ok": false, "problems": ["tier5 execution: amt mismatch: HO 5400.00 vs RB 5100.00"], "notes": []}

    ok: false means the job does not change hands. Send the instruction again. With the right amount in the read-back the reply is {"ok": true, "problems": [], "notes": []}: roger, wilco.

  3. Build the readback for the other side, if that agent runs code. It carries the values the act will use and adds h=, the fingerprint of the message as received; a value the hand-over leaves to the receiver, such as the account on file, the receiver adds itself. 
    curl -s https://rogerwilco.crox.io/make-rb \
  -H 'content-type: application/json' \
  -d '{"ho": "RW1 HO scheduler-1 p=pay from=scheduler to=payer item=inv:MD-2026-057 ask=PAY rb=exec sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057 apref=FD-0929", "id": "payer-1", "profile": "pay"}'
    {"rb": "RW1 RB payer-1 re=scheduler-1 from=payer to=scheduler item=inv:MD-2026-057 ask=PAY p=pay h=a7a82de76607 sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057 apref=FD-0929"}

Every endpoint, with its inputs and outputs: the API reference. The gate, which checks lines against the document they came from, is POST /gate.

Python

One package, standard library only.

  1. Install it. 
    pip install rogerwilco

    Until it is on PyPI: pip install git+https://github.com/afieldofdreams/rogerwilco

  2. Build a readback and check it. 
    import rogerwilco as rw

ho = "RW1 HO scheduler-1 p=pay from=scheduler to=payer item=inv:MD-2026-057 ask=PAY rb=exec sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057 apref=FD-0929"

# the receiving agent sends this back before it does anything
rb = rw.make_rb(ho, "payer-1", "pay")

# the sending side checks it in code
problems, notes = rw.check_rb_full(ho, rb, "pay")
print(problems or "roger, wilco")
    roger, wilco
  3. See a miss. Change one digit in the read-back and check again. 
    problems, notes = rw.check_rb_full(ho, rb.replace("5400.00", "5100.00"), "pay")
print(problems)
    ['tier3 echo: amt mismatch: HO 5400.00 vs RB 5100.00']

    The fingerprint h= still matches here because the hand-over itself was not changed, only the read-back; a message corrupted on the way fails the fingerprint check as well. The same functions on the command line: rogerwilco validate "<line>" --profile pay, rogerwilco make-rb "<ho>" payer-1 --profile pay, rogerwilco check-rb "<ho>" "<rb>" --profile pay.

Your agent

An agent that cannot run code calls the hosted tools. An agent that can run code uses the skill folder. Any agent can learn the format from a short legend pasted into its prompt.

  1. Claude Code: add the tools in one line, then ask the agent to use rogerwilco when it hands work to a subagent. 
    claude mcp add --transport http rogerwilco https://rogerwilco.crox.io/mcp

    Eight tools arrive: validate, gate, check_rb, make_rb, check_ho, check_dn, legend, to_json. Any other MCP client takes the same URL.

  2. Or copy the skill folder into your project, so the agent reads it on its own. 
    git clone https://github.com/afieldofdreams/rogerwilco
cp -r rogerwilco/rogerwilco .claude/skills/rogerwilco
  3. Any agent at all: put the legend in its system prompt. That is all the other side needs. 
    curl -s "https://rogerwilco.crox.io/legend?profile=pay"
    rogerwilco RW1. One line per message: RW1 <TYPE> <id> [re=<id>] from=<agent> to=<agent> [item=<ref>] key=value ... [// tail]. ...
HO handoff: requires from to item ask; ...
RB readback: requires re from to item ask; ...
