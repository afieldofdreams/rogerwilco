Same line, four kinds of work

The shape of a line never changes: version, type, id, who it is from and to, what it is about, then labelled facts. The eight message types and the few basic words (the asks, the reasons for saying no, the done states) describe the act of handing work over, not the work itself. Everything about one kind of work lives in a profile: a small file that adds the labels, the allowed words and the asks for that work. The same checks run on all of them. Below, the same loop in four kinds of work. Every line on this page was run through the checker before the page was written.

Paying bills

profile pay: scheduler, payer, the finance director as human

The irreversible step is releasing a payment. The profile adds amounts, currencies, accounts, dates, and the five answers a finance director may give (approve, decline, hold, reject, call back).

Hand over

Release the Marlow payment, read it all back first.

RW1 HO scheduler-1 p=pay from=scheduler to=payer item=inv:MD-2026-057 ask=PAY rb=all sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057

Read back

The payer repeats every fact, with the fingerprint.

RW1 RB payer-1 re=scheduler-1 from=payer to=scheduler item=inv:MD-2026-057 ask=PAY p=pay h=a6cf98835d6c sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057

Done

What was actually paid, to where, when.

RW1 DN payer-2 re=scheduler-1 p=pay from=payer to=scheduler item=inv:MD-2026-057 out=OK amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057

Releasing software

profile deploy: release, operator, on-call

The irreversible step is the deploy to production, or a migration with no way back. The profile adds environments, versions, the change window and the approval reference.

Hand over

Deploy v2.4.1 to production in the 02:00 window under change approval CAB-0931.

RW1 HO release-1 p=deploy from=release to=operator item=svc:api ask=DEPLOY rb=all env=PROD ver=v2.4.1 prev=v2.4.0 win=20261007T0200-0230 apref=CAB-0931

Read back

The operator repeats it; the release agent's program checks it before the window opens.

RW1 RB operator-1 re=release-1 from=operator to=release item=svc:api ask=DEPLOY p=deploy h=ef37e04abf27 env=PROD ver=v2.4.1 prev=v2.4.0 win=20261007T0200-0230 apref=CAB-0931

Ask

A migration has no down migration. The operator asks the human, with the allowed answers, rather than deciding.

RW1 AQ operator-1 re=release-1 p=deploy from=operator to=human item=mig:0142 need=ENUM opts=APPROVE+HOLD mig=0142 down=N // migration 0142 has no down migration; approve as irreversible, or hold?

Done

What is running now, and its health.

RW1 DN operator-2 re=release-1 p=deploy from=operator to=release item=svc:api out=OK env=PROD ver=v2.4.1 prev=v2.4.0 state=UP

Clinical notes

profile clin: extractor, reviewer, the record

Here nothing is handed over; the lines are the record. One line per statement the note makes, with its kind, whether it is affirmed or denied, how certain, about whom, when, the value, and a pointer to the exact words. A program refuses any line whose words are not on the line of the note it points to.

A measurement

HbA1c 7.2% on line 14 of document 3.

RW1 ST extractor-5 p=clin from=extractor to=record item=meas:hba1c act=OBS pol=POS cert=CERT subj=PT time=CUR res=7.2 unit=% src=doc:3#l14 // HbA1c 7.2%

A denial

No chest pain: a negated symptom, reported by the patient.

RW1 ST extractor-6 p=clin from=extractor to=record item=sym:chest-pain act=RPT pol=NEG cert=CERT subj=PT time=CUR src=doc:3#l9 // not had any chest pain

Done

The whole note translated: 24 lines.

RW1 DN extractor-7 re=lead-1 p=clin from=extractor to=human item=doc:3 out=OK n=24

A knowledge graph

profile pform: the stances of an assistant that tends a graph

Agents handing graph nodes to each other for scoring, enrichment or pruning. The profile adds the node's stage, status, importance and heat, and the asks those agents use.

Hand over

Triage asks the strategist to score node 4102, which has stalled for 15 days.

RW1 HO TRI-01 p=pform from=TRI to=STR item=pensive:4102 ask=SCORE4 stg=OPT os=NOW imp=7 heat=HOT stall=15d touch=20260914

Read back

The strategist repeats it.

RW1 RB STR-01 re=TRI-01 from=STR to=TRI item=pensive:4102 ask=SCORE4 p=pform h=25e742ea2f7d

Done

Scored, with the score in the note and the node as the artefact.

RW1 DN STR-02 re=TRI-01 p=pform from=STR to=TRI item=pensive:4102 out=OK art=pensive:4102 // scored 31 of 40: capability 9, values 8, user value 7, revenue 7

Write your own

A profile is a JSON file. This is the deploy profile with the extras trimmed: three enums (one of them the closed answers a human may give), two asks, three labels, two agents. Put it in the profiles/ folder next to the others and every tool knows it: the validator, the readback check, the legend, the gate.

{
 "profile": "deploy",
 "extends": "RW1",
 "enums": {
  "env": {
   "DEV": "development",
   "STAGE": "staging",
   "PROD": "production"
  },
  "ans": {
   "APPROVE": "yes, proceed as asked",
   "DECLINE": "no, do not proceed",
   "HOLD": "wait; do nothing until told"
  }
 },
 "asks": {
  "DEPLOY": "deploy the named version to the named environment in the change window",
  "ROLLBACK": "return the environment to the previous version"
 },
 "slots": [
  {
   "key": "env",
   "type": "enum:env",
   "desc": "target environment",
   "on": [
    "HO",
    "RB",
    "ST",
    "DN"
   ]
  },
  {
   "key": "ver",
   "type": "token",
   "desc": "version or commit to deploy",
   "on": [
    "HO",
    "RB",
    "ST",
    "DN"
   ]
  },
  {
   "key": "win",
   "type": "token",
   "desc": "change window as YYYYMMDDTHHMM-HHMM",
   "on": [
    "HO",
    "RB",
    "DN"
   ]
  }
 ],
 "agents": [
  "release",
  "operator"
 ]
}
  • enums are the allowed words for a label. ans is special: when a profile defines it, every question to a human takes its options from it and every answer must be one of them.
  • asks are the jobs in this kind of work. They join the basic ones (DRAFT, REVIEW, FIX...), which stay available.
  • slots are the labels, each with a type (enum:env, token, money, date, int:1-10, bool, list:...), a description the legend prints, and the message types it may appear on.
  • agents are the names allowed in from= and to=. human is always allowed.

A profile can add words; it may not change what a basic one means. Then: rogerwilco legend --profile deploy prints the one-page legend for an agent's prompt, and rogerwilco validate "<line>" --profile deploy checks a line against it.
