A way for AI agents to say exactly what they are about to do, so a program can check it before they do it.

AI agents are starting to do real things: pay a bill, change the bank account a supplier is paid into, send an email to a customer. Some of those cannot be undone. Before an agent does one of them, two things should be true. The agent that asked and the agent that acts agree on exactly what is going to happen. And afterwards there is a record of exactly what did happen.

rogerwilco does that with three tiny messages. Each one is a single line of text. Every fact has a label. A program can read it like a form, not like a paragraph.

1. Hand over scheduler to payer

"Pay invoice MD-2026-057: 5,400.00 pounds, gross, to account 40-12-88 / 61102938, on 2 October. Read it all back before you do anything."

RW1 HO scheduler-1 p=pay from=scheduler to=payer item=inv:MD-2026-057 ask=PAY rb=all sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057

2. Read back payer to scheduler

"Paying invoice MD-2026-057, 5,400.00 pounds, gross, to 40-12-88 / 61102938, on 2 October."

RW1 RB payer-1 re=scheduler-1 from=payer to=scheduler item=inv:MD-2026-057 ask=PAY p=pay h=a6cf98835d6c sup=marlow amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057

checkA program compares this line with the first one, label by label. h= is a fingerprint of the message as it arrived, so a digit changed on the way shows up too. If anything differs, the payment waits and the scheduler sends the instruction again. If it all matches: roger, wilco.

3. Done payer to scheduler

"Paid 5,400.00 pounds to 40-12-88 / 61102938 on 2 October, reference MD-2026-057."

RW1 DN payer-2 re=scheduler-1 p=pay from=payer to=scheduler item=inv:MD-2026-057 out=OK amt=5400.00 cur=GBP kind=GROSS acct=40-12-88/61102938 paid=20261002 ref=MD-2026-057

checkThe done message carries the values as they were actually used, not as they were asked for, so a program can check those against the instruction too. That is the second loop: not just "I understood", but "here is what I did". In our fifth study that check ran on every done message; writing it into the rulebook is the next change.

The names come from the radio. When a pilot is told "descend to 3,000 feet, QNH 1013", the pilot says it back and the controller listens for a mistake. Roger means "I received it". Wilco means "I understood it and I will do it". Then, in the flight deck, "QNH 1013 set" is called out and the other pilot checks the dial. Agents can do the same, and a program can do the listening.

9 of 16, then 0

We tested it. We planted sixteen faults in handovers just before a payment, a bank-detail change and a supplier email: a wrong digit, the wrong account, the wrong date, a message meant for someone else. Without a readback, nine of the sixteen became a wrong act that could not be undone (fourteen with a smaller model). With the line read back and checked by a program, none did, on either model, and no correct handover was wrongly held up. What we did and what happened, and the four studies before it, including the one that found that with a strong model the lines do not save money. What they save is mistakes.

A profile is the word list for one kind of work. core is the basics, pform is for a knowledge graph, pay is for paying bills, clin is for clinical notes. The two message panels use the one you pick.

Check a line

Pick an example or write your own, then press Check. You will see whether a program accepts it and what it read from it. Try changing a word to one that is not on the list. "Make readback" writes the reply the other agent should send. "JSON" shows the same message as data. "Fingerprint" is the short code that proves a message arrived unchanged.

Readback options

Check a readback

This is what the sender's program does before it lets go of a job. Paste the hand-over (HO) you sent and the read-back (RB) that came back. Four checks run in order: the reply is to the right message from the right agent; the message arrived unchanged; every fact was repeated back correctly; and, if you asked for it, the receiver understood the brief the way you meant it. The first two are roger, the last two are wilco. Pick the examples that fail to see what a miss looks like.

Check lines against a document

When an agent turns a document (an email, an invoice, a clinical note) into lines of fact, each line says which line of the document its words came from. Paste the document and the lines, and a program checks that every pointer is real and the words are really there. Lines of the document are counted from 1, blank lines included. For the pay profile it checks pointers into an inbox export instead, and that net plus VAT equals the total.
