Typed compression for agent handoffs

Does a codebook-governed wire format beat English for agent-to-agent messages? A prototype (rogerwilco) and a five-format test on 240 synthetic Pensive handoffs.

In plain words

What we didWe wrote the same 240 handover messages five ways: plain English, JSON, a rogerwilco line, a form made of symbols, and a very tight form where every fact sits in a fixed position. We counted the tokens each way costs, checked that every message survives being turned into data and back, and gave 60 of them to a model that had not seen the format and asked what it would do with each.

What happenedA line costs about 29% fewer tokens than English; the tight form about 59% fewer. Every message survived the round trip. The strong model understood every form perfectly. The small model lost its place in the tight form in one run of two, getting four messages in ten wrong; in the other run, one in twelve.

What it meansThe saving per message is small: 20 to 40 tokens. A hundred handovers a day save less than one resend of a system prompt. So tokens are not the reason to use lines. The reason is that a program can check them. The tight form is for programs talking to programs, not for models.

EGLL 271220Z 24012KT 9999 FEW025 SCT040 17/09 Q1016A METAR. Fixed positions, closed vocabularies, one line. Sixty years old and still read by both humans and parsers. This is the shape being tested.

Decision. Adopt the keyed form (HO|TRI>STR|P4102|stg=OPT|…) as the P-Form handoff wire in the Pensive Protocol. Use the positional form with checksum only where code, not a model, is the reader. Drop glyphs. Do not pursue latent communication. Next validation gate: real Pensive nodes, three runs per cell, Claude's own tokenizer.

What changed from the conversation. Two claims I made earlier were wrong. Savings are 29 to 60 percent, not 80. And a small model read the glyph form perfectly, twice; glyphs fail on legend cost and tokenizer dependence, not on comprehension.

1. Question and scope

The starting point was "agents talking English is pointless, they need their own language." The literature makes that a three-way choice: emergent languages (agents invent codes under pressure), latent communication (agents pass hidden states, not text), or a governed dialect (a fixed codebook that both sides load). This study tests only the third, because it is the only one that runs on a hosted API and stays readable. M-Form is the precedent: a semantic compression format for medical records. The technique underneath it is domain-agnostic, so the prototype is built as a generic schema-driven codec, with P-Form (Pensive handoffs) as its first schema.

Three things count as validation, agreed up front: token reduction against English and JSON; lossless round trip; and decision parity, where a blind receiving agent makes the same call from the compact message as from the English one.

2. Prior art

Typed positional formats. METAR, FIX, HL7 v2 and ATC phraseology all do the same thing: closed vocabularies, fixed slot order, a delimiter, optional free-text tail. They are the prior art for the wire shape, and nobody owns them.

Learned prompt compression. LLMLingua (Microsoft, 2023) drops low-perplexity tokens with a small model and reports up to 20x compression on few-shot prompts with under 2 percent loss. It is lossy and unstructured, so it suits retrieved context and conversation history, not typed handoffs where a dropped field is an error.

Structural compression. TOON (2025) is a lossless re-encoding of the JSON data model that reports about 40 to 46 percent fewer tokens than JSON on uniform arrays with retrieval accuracy at parity. Its authors note that models process CSV-like tables less reliably than headed forms, and a 2026 benchmark found TOON's advantage shrinks in short contexts once the format legend is charged to the prompt. That legend tax turns out to be the main design constraint here too.

Latent communication. Interlat (ACL 2026) passes an LLM's last hidden states between agents, compressing to eight latent steps with up to 24x communication speedup and better task success than fine-tuned natural-language baselines. StateBridge (2026) does it training-free across model families. The "Beyond Tokens" survey (June 2026) frames this as the direction of travel. Two caveats matter for us: it needs weight-level access, which a hosted API does not give, and "When Latent Agents Lie" shows hidden payloads can diverge from the visible commitment, so the audit gap is real. A mechanistic study of a four-agent latent system found most of the channel's dimensions unused and the representations dominated by the base model's geometry, which suggests the bandwidth argument is weaker than it sounds.

Emergent language. GlossoGen (September 2026) shows Claude and GPT agents drifting from English to unintelligible codes under budget pressure in a fully cooperative task, with no adversarial pressure at all. This matches the decade-old MARL result (Lazaridou 2017, Kottur 2017) that self-invented protocols optimise for task efficiency and lose compositionality unless externally constrained. That is the case against "let the agents invent it." The codebook has to be authored.

3. Method

Codec. rogerwilco is about 250 lines of Python. A JSON schema declares enums and message types; each type declares typed slots (enum, int with range, days, date, list, text). The codec encodes a dict to one line, decodes it back, rejects anything that fails validation, and can emit a delta against a previous state. Two wire styles share one schema:

  • Keyed. Pipe-delimited, key=value, optional fields omitted. Self-describing enough to read cold.
  • Tight. Space-separated, every slot in fixed position, - for absent, optional 3-character CRC. METAR-shaped.

Three comparison renderings of the same data: English prose (template-generated with varied phrasing, so it is more regular than real stance writing), compact JSON with full field names, and a glyph form where every key and enum code is a single Unicode symbol, to test the hieroglyph hypothesis directly.

Data. 240 synthetic handoffs, balanced across six receiver outcomes. Fields follow the Pensive Protocol: stance codes, pipeline stage, operational status, importance, heat, stall days, confidence, ask, keep-assigned, due date, source view, blocked-by, note.

Tokens. Counted with OpenAI's o200k_base and cl100k_base via tiktoken. Claude's tokenizer is not public; two independent BPE vocabularies are used to show which effects are tokenizer-specific. Treat absolute numbers as proxies.

Parity. Sixty messages (ten per outcome), rendered in all five formats. Each batch went to a fresh subagent that had not seen the codec, with a six-rule ordered receiver policy, the format legend, and an instruction to read rather than run code. Haiku 4.5 ran twice per format, Sonnet once. Scored against the policy applied programmatically.

In words: the same message costs 69 tokens in English, 65 in JSON, 49 as a line, 42 in symbols and 28 in the tight form. The legend is what you pay once to teach an agent the format; break-even is how many messages it takes to earn that back against English.

In the keyed form, 35 percent of tokens are delimiters: |, =, > and + each cost a token of their own, with a few = merging into the letter after them. The tight form wins by removing them, not by shortening words. A space-prefixed short code is usually one token on both vocabularies, so ACT and action cost the same; abbreviation buys almost nothing on its own.

Delta encoding for a repeated state read (a heartbeat re-reading a node it already holds) took the same message from 43 to 21 tokens by sending only identity plus changed fields.

4.2 Fidelity

Round trip was exact on 240 of 240 messages for the keyed codec and 480 of 480 for the tight codec (with and without checksum). Corruption tests differ by design:

  • Keyed: 697 mutated lines, 629 rejected (90%). Of the 68 accepted, 58 were a dropped optional field. A keyed format cannot see that an optional field went missing; that is structural, not a bug.
  • Tight without checksum: 698 mutations, 185 decoded silently to wrong values (27%). Of those, 170 were a single digit changed in a numeric field and 15 were two fields swapped; every dropped or inserted field was rejected by the arity check. The keyed test did not include digit flips, and no unchecked format can catch them, so the 90% and 27% figures are not like for like.
  • Tight with the 3-character CRC: 699 mutations, zero silent errors. A 3-character CRC has roughly a 0.08% collision chance per corrupted line, so this is strong rather than absolute.

In words: the strong model read every form right every time. The small model read English and the symbol form right every time, got one message in twelve wrong in JSON, and in the tight form got four in ten wrong in one run and one in twelve in the other.

Sonnet was perfect in every format, so at that tier the wire format is a cost and safety decision, not a comprehension one. Haiku's errors cluster into three kinds:

  • Column miscount. Haiku tight run 1: 20 of 25 errors were WAIT applied to unblocked nodes. Fourteen positional slots with - placeholders and it lost its place. Run 2 did not repeat it, which says the format is fragile at this tier, not unreadable.
  • Salient token beats rule order. Across JSON, keyed and tight, a node at stage DONE was routed CLOSE (rule 5) even when rules 1 to 4 should have fired first. It never happened in English, where "pipeline stage done" sits inside a sentence, and never in glyph form, where the stage is a Greek letter. A bare DONE token reads like a verdict.
  • Two-condition numeric rule missed. JSON only, both runs: ESCALATE (stall ≥ 14 and importance ≥ 7) read as ACCEPT. Full field names did not help.

One enum collides with a decision label: the operational status WAIT is spelled the same as the WAIT outcome. It explains only 2 of the 20 column-miscount errors, so it is not the cause, but it is a schema hygiene fault and cheap to fix. The stronger signal for the miscount is that all 20 mispredicted messages had a number in the source-view column, immediately before the blocked-by column, against 7 of the 25 correctly routed non-WAIT messages. Haiku read the neighbouring number as a blocker.

5. Findings

  1. Structural compression gives 29 to 60 percent, not 80. This matches TOON's published range and is the ceiling for lossless typed messages of this size. The earlier 80 percent figure came from comparing a verbose prose example against a hand-tuned line.
  2. Handoff tokens were never the cost. At 20 to 40 tokens saved per message, a hundred handoffs a day save less than one system-prompt resend. The delta result (43 to 21 tokens) points at the real target: repeated node state reads in the heartbeat loop, per the April cost model.
  3. The hieroglyph idea is half right. Glyphs did save tokens on o200k and were read perfectly by both models, so "off-distribution and unreadable" was wrong. But the saving is tokenizer-dependent (4 percent over keyed on cl100k), the legend is 1.7x larger, and a glyph is usually two tokens where a three-letter code is one. Density on the page is not density in tokens.
  4. Positional is cheapest and most fragile. Tight form cuts the keyed cost by 43 percent and, with a CRC, is the only form that catches value corruption. But a small model miscounted columns in one run of two. It belongs on code-to-code paths, or on model-read paths only after header echo or column reduction is tested.
  5. Compact formats need label hygiene. No enum value should share spelling with an outcome the receiver can choose, and terminal-sounding codes (DONE) pull small models past earlier rules. Rename opstatus.WAIT before adoption and test a neutral spelling for the done stage.
  6. Legibility survives. The keyed and tight forms decode to the same dict, JSON and glyph are renderings of it, the codebook lives in the Protocol, and a human can read the keyed form cold. This is the answer to "your own language": a governed dialect, not an emergent one. GlossoGen shows what the alternative drifts into.
  7. Latent communication is not available to us. It needs hidden-state access. On a hosted API the text channel is the only channel, so the question is which text, and this study answers that.

Validation gate for v0.2 (one week).

  • Real Pensive nodes, read-only pull, n ≥ 500, sampled from views 119, 120, 121 and 97.
  • Three runs per cell, Haiku and Sonnet, with 95 percent bootstrap intervals. Add a tight-with-header variant to see if header echo fixes the column miscount.
  • Token counts from Claude's own count-tokens endpoint, replacing the tiktoken proxies.
  • Measure a full heartbeat cycle end to end with delta-encoded state reads, not per-message savings. That is the number that decides whether this is worth running.
  • Pass criteria: ≥ 95 percent parity on Haiku across all three runs for the adopted form; ≥ 25 percent reduction on real heartbeat traffic; zero silent corruption on the code path.

Do not pursue. Glyphs (legend cost, tokenizer dependence, no comprehension advantage). Latent channels (no access, audit gap). Agent-invented codes (drift).

7. Limitations

  • Synthetic data. The English rendering is template-generated, so it is more regular and more parseable than real stance prose. Real handoffs will likely widen the token gap and could narrow the parity gap.
  • Proxy tokenizers. Absolute counts will differ on Claude's vocabulary; the ordering of formats is unlikely to.
  • Small parity samples: 60 messages per cell, two runs for Haiku, one for Sonnet. The Haiku tight result (58 then 92) shows the variance is large. Treat Table 2 as a screen, not a measurement.
  • Receivers were subagents instructed to read rather than compute. One agent made a stray reporting call and confirmed on query that it decoded by hand; none reported running code, but this was not enforced by tooling.
  • The receiver policy is six rules. Real stance decisions are less crisp, which favours English more than these numbers suggest.
