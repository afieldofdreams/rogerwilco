Does a verified readback make agent handoffs better?

A controlled pilot of rogerwilco against prose handoffs, with planted faults, blind grading and one correction cycle. Effect confirmed where misreads occur; the typed form's edge over a prose readback is real but narrow; the check's precision on small models needs a design change.

In plain words

What we didWe gave agents briefs with traps in them. For example, the message said "120 words" but the attached brief said "150 words, no more". Then we handed the job over three ways: in plain English with no readback; in plain English with the receiver writing back what it understood, judged by another model; and as a rogerwilco line with the receiver reading it back and a program checking it.

What happenedWithout a readback, 4 of 36 jobs were done on the wrong reading and stayed wrong. With a readback of either kind, every misread was flagged and fixed with one correction. The line version prevented two of them before any check, probably because having to put a number after len= made the receiver read the brief instead of trusting the message (one trap, two runs: a strong hypothesis, not a result). On the small model the program over-flagged terse readbacks, ten false alarms in eleven; a rule change planned for the next version would remove them.

What it meansReading back works. The line is a little better than a paragraph, mainly because it forces a value. A readback proves the receiver understood; it does not prove it will do it. A small model read a rule back correctly five times and then ignored it. That gap is what the fifth study looks at.

Result in one line. Both readback mechanisms caught every handoff misunderstanding that reached an output (4 of 4) and drove handoff defects to zero after one correction; the no-readback baseline kept all of its 4. The typed form (C) was the only arm with zero handoff defects before any check, because deriving a typed len: value made receivers read the brief where prose let them rationalise the tail. Its check ran with zero false alarms on Sonnet and ten of eleven on Haiku, whose readbacks are terse.

Decision. Continue to v0.2 with three changes: split flag severity (contradiction voids, missing set value asks to confirm), add a done-time acceptance check against the same criteria, and ship the 400-token legend rather than the skill file as the receiver prompt. Then replay on real Heartbeat handoffs and add a non-Claude receiver.

1. Design

Two domains: landing-page copy and supplier-invoice extraction. Six variants each: a clean brief and five planted faults (a constraint only in the artifact, a near-miss number, a tail-versus-artifact contradiction, a rule buried mid-brief, a categorical rule). Hidden acceptance criteria per variant, part code-checkable, part semantic. The artifact is authoritative where it disagrees with the handoff tail.

Three arms on the same briefs. A: prose handoff, no readback. C: rogerwilco HO with rb=acc keys=…; receiver emits a readback first; the sender's withheld criteria are compared in code; one correction cycle by re-issued HO. D: prose handoff plus a prose "state what you understand" paragraph; a blind model judge compares it with the criteria; one prose correction cycle. D is the control that separates the typed format from the readback ritual.

Receivers: fresh Sonnet agents, two runs per cell (72 handoffs), and fresh Haiku agents, one run per cell (36). Each receiver saw only the brief, the handoff and, in C, the skill file. Grading: code for word counts, formats, sets, amounts, dates and forbidden strings; Opus, blind to arm, for semantic criteria (first sentence names the Monday problem, regulated-industry proof, voice). Corrections were sent to the same agent after its first output, so correction cycles are measured post-work; the pre-work saving is modelled, not measured.

3. Findings

  1. Readbacks work, in either form. Four handoff misunderstandings reached an output across the readback arms; all four were flagged and all four were fixed by one correction. The baseline had no mechanism and kept its four. Rate of handoff defects: A 4 of 36, D 3 of 36 before correction and 0 after, C 1 of 36 before and 0 after.
  2. The typed form changes behaviour at derivation, not only at the check. On Sonnet, C had nothing to catch: forcing a number into len: made receivers take the brief's number. The prose readback let the same model articulate the conflict and still choose the tail's number. This is the clearest evidence that the format itself, not just the ritual, matters. It rests on one fault type and two runs, so treat it as a strong hypothesis for v0.2 to test on more faults.
  3. Code checks beat model judges on precision, for capable receivers. C's checker ran 24 Sonnet readbacks with zero false alarms. D's judge produced one false alarm on Sonnet (it demanded a nuance the brief did not require) and misread the criteria once on Haiku. A model judge is also a second model call per handoff; the code check is free.
  4. The check's precision collapses on terse readbacks. Haiku's readbacks list a few criteria and stop. Ten of eleven flags on Haiku were gaps on set values the receiver went on to honour. The one true flag was a contradiction (len 120 versus 150). Design change: a contradiction or a missing key voids the readback; a missing set value triggers a one-line confirm, not a re-issue. Applied retrospectively, Haiku's false alarms fall from ten to zero and the true detection stays.
  5. A readback verifies understanding, not execution. Haiku stated must:monday-problem in five readbacks and then failed to put it in the first sentence. No pre-work check can catch that. The same typed criteria make a done-time check mechanical for the code-checkable ones and a targeted judge call for the rest. v0.2 should add it to DN.
  6. The comprehension readback is a cost, not a saving. With the legend instead of the skill file, C costs about twice A per handoff; with the skill file, five times. It pays back only when it prevents rework. On a 120-word paragraph the rework is cheap; on a spec, a build or a scheduled fire it is not. The token savings measured earlier live in state and logs, which this pilot did not exercise.
  7. Two harness bugs were found and fixed during the run and are reported rather than hidden: plural matching (amounts versus amount) caused two false alarms on Sonnet before the fix; the second readback was initially compared against the original HO instead of the re-issued one.

4. Limits

  • 36 handoffs per arm and one Haiku run per cell. The near-miss and contradiction cells carry the whole signal; the other cells are flat because both models read these briefs correctly in every arm.
  • The near-miss brief said "150 words, no more", which a receiver can defensibly satisfy with 120. The behavioural divergence and its visibility are real; the defect label depends on sender intent. v0.2 uses "between 140 and 150".
  • Claude receivers only, two domains, criteria written by the experimenter. Same-model pairs share their misreads.
  • Corrections ran after the work was done. The pre-work catch is what a runtime gives you; here it is inferred from flag timing.

5. v0.2 changes and next gate

  • Severity split in check-rb: void on contradiction or missing key; confirm on missing set value.
  • Done-time acceptance: DN carries acc= self-attestation; check-dn runs code checks against the sender's criteria and routes semantic ones to a judge.
  • Receiver prompt is the generated legend, not SKILL.md; the skill stays on the sender side.
  • Corpus v2: unambiguous near-miss, three more fault types (stale artifact version, conflicting artifacts, a constraint stated as an example), two more domains (code review, ops runbook).
  • Replay 50 historical Strategist-to-Architect handoffs from the Heartbeat log with sender-written criteria; add a GPT and a Gemini receiver reading the legend cold.
  • Pass criteria for adoption in the Heartbeat: handoff defects after correction at zero, false alarms under 10 percent on the weakest receiver in use, and net tokens per fire below the prose baseline once state lines replace narration.
